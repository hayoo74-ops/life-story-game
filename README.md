# LIFE STORY
나의 인생을 담은 모바일 횡스크롤 게임

안재원의 기록을 바탕으로 만든 모바일 2D 횡스크롤 스토리 어드벤처입니다. **챕터 1은 시작, 탐험, 대화, 선택, 수집, 완료까지 플레이할 수 있습니다. 챕터 2–8은 준비 중입니다.**

HTML5 · CSS3 · JavaScript · Phaser 3 · Vite · LocalStorage · PWA. 그래픽은 외부 이미지 없이 코드에서 직접 그리는 오리지널 픽셀아트이며, 음악은 Web Audio로 합성하는 짧은 오리지널 선율입니다.

## 실행

Node.js **22.12 이상**을 권장합니다.

```sh
git clone https://github.com/hayoo74-ops/life-story-game.git
cd life-story-game
npm ci
npm run dev
```

터미널에 표시되는 로컬 주소를 엽니다. 기본 주소는 `http://localhost:5173`이며 포트를 사용 중이면 달라질 수 있습니다. `index.html`을 파일로 직접 열면 ES 모듈과 PWA가 정상 동작하지 않습니다.

같은 Wi-Fi에 연결된 스마트폰에서는 개발 PC의 LAN IP와 Vite 포트로 접속할 수 있습니다. 예를 들어 **실제 PC IP가** `192.168.0.10`인 경우 `http://192.168.0.10:5173`입니다. 방화벽에서 해당 포트의 연결이 허용되어야 합니다. 이 예시 주소는 배포된 접속 주소가 아닙니다.

배포용 빌드와 확인:

```sh
npm run build
npm run preview
```

`dist/`에 완성된 정적 게임이 생성됩니다. 프리뷰 기본 포트는 4173입니다.

## 플레이 방법

1. **새 게임 시작하기**로 사진첩 오프닝을 진행합니다.
2. 집에서 할머니에게 다가가 **✦ 대화 / 조사**로 인사합니다. 선택지를 누른 뒤 끝까지 대화를 진행합니다.
3. 집 → 골목 → 놀이터 → 문구점 → 학교 앞 거리로 걸어갑니다. 각 장소 끝의 화살표 표지판에 다가가 ✦ 버튼을 눌러 이동합니다. 왼쪽 표지판으로 이전 장소에 돌아갈 수 있습니다.
4. 학교 앞 오른쪽의 **다음 페이지**를 조사하면 챕터 1이 완료됩니다.
5. 완료 후에도 동네로 돌아가 남은 기억을 수집하거나 추억 앨범을 다시 읽을 수 있습니다.

기억의 조각 8개는 모두 선택 수집입니다. 하나도 수집하지 않아도 메인 이야기를 완료할 수 있습니다.

| 조작 | 스마트폰 | 키보드 |
|---|---|---|
| 이동 | ← / → 길게 누르기 | 방향키 / A, D |
| 점프 | ↟ | Space / W / ↑ |
| 대화·조사·이동 | ✦ | E |
| 대화 다음 | 대화창 터치 | Enter / E |
| 선택 | 선택지 터치 | Tab으로 버튼 선택 후 Enter |
| 일시정지·메뉴 | Ⅱ / ☰ | Esc |

이동과 점프를 동시에 누를 수 있습니다. 터치 해제·취소·창 전환 시 입력을 해제합니다. 대화와 메뉴가 열리면 이동과 물리를 멈춥니다.

## 완성된 기능

- 현재의 사진첩 → 1997년 부산 출생 → 어린 시절 집으로 이어지는 오프닝
- 서로 연결된 5개 장소와 양방향 이동, 장소별 픽셀아트
- 어린 재원의 대기·걷기·점프 애니메이션, 경계·바닥 충돌, 부드러운 카메라
- 다층 배경, 도시의 산과 집, 실내 창가, 나무, 가로등, 문구 진열대 등 코드 기반 그래픽
- 할머니·할아버지·동네 아이·문구점 주인과의 한국어 대화, 선택지, 진행 후 달라지는 대사
- 가족사진·TV·장난감·책상·가로등·그네·연필·학교 가방, 8개 기억의 회상과 앨범 재열람
- 메인 목표, 완료 이벤트, 챕터 1 마무리 및 제작 안내
- 모바일 세로 화면과 가로 전환, 게임 화면과 분리한 터치 조작부, 멀티터치
- 일시정지, 소리, 큰 대화 글자, 화면 움직임 줄이기
- 낮·해 질 무렵·밤·낮과 밤의 흐름·비 분위기, 실내외 조명과 날씨 효과
- 진행·좌표·이벤트·퀘스트·기억·설정 자동 저장, 이어하기, 손상·상위 버전·저장 차단 처리
- 첫 온라인 방문 후 리소스를 캐싱하는 서비스 워커와 PWA 설치 매니페스트
- 외부 음원이 없어도 동작하는 배경음·효과음 재생 시스템, 기본 무음
- 후속 챕터 목록과 별도 구조화된 인생 기록 원자료

## 미완성 및 검증 한계

- **챕터 2–8의 맵·이벤트·대화·플레이는 아직 구현하지 않았습니다.** 목록에만 준비 중으로 표시합니다.
- 실제 사진 기반 외형, 각 시기의 정교한 캐릭터 디자인, 성우 음성, 긴 BGM은 없습니다. 유년·학생·청년·성인용 기본 픽셀 캐릭터 생성 구조는 마련했습니다.
- 제공되지 않은 구체적인 사건·연도·장소·대화는 사실로 만들지 않았습니다. 행정구가 일치하지 않는 학장동 기록은 구를 생략했습니다.
- 실제 Galaxy S24 Ultra 기기나 삼성 인터넷에서의 실기기 검증은 하지 않았습니다. Chromium의 모바일 뷰포트 및 실제 멀티포인트 터치 이벤트를 이용해 검증했습니다.
- 이 작업 환경에는 외부에서 접속할 수 있는 미리보기 전달 도구와 Sites 로컬 배포 helper가 없어 호스팅 배포를 수행하지 않았습니다. 생성한 접속 URL은 없습니다.
- 저장은 기기·브라우저·사이트 주소별 LocalStorage입니다. 클라우드 동기화나 다른 기기로의 자동 이전은 없습니다. 브라우저 데이터 삭제 시 저장이 사라집니다.
- PWA 설치 가능 여부와 오프라인 캐시 보존은 브라우저 정책·남은 저장 공간에 따라 달라집니다. 새로운 리소스는 온라인에서 내려받아야 합니다.

## 배포와 오프라인 플레이

`npm run build` 후 **`dist/` 내용 전체**를 HTTPS를 지원하는 정적 호스팅의 사이트 루트에 배포합니다. 예를 들어 Cloudflare Pages, Netlify, 정적 Nginx 호스팅을 사용할 수 있습니다.

| 설정 | 값 |
|---|---|
| 설치 | `npm ci` |
| 빌드 | `npm run build` |
| 출력 디렉터리 | `dist` |
| Node 버전 | 22.12 이상 |
| 서버 API·환경 변수 | 필요 없음 |

1. HTTPS 사이트에 온라인으로 접속해 로딩이 끝날 때까지 기다립니다.
2. **오프라인 준비 완료** 안내를 확인합니다.
3. Chrome / 삼성 인터넷의 메뉴에서 **앱 설치 / 홈 화면에 추가**를 선택합니다. 게임 설정에도 설치 진입 버튼이 있습니다.
4. 이 브라우저의 캐시와 저장 데이터를 유지하면 오프라인으로 게임을 다시 열어 이어할 수 있습니다.

서비스 워커는 HTTPS 또는 `localhost`에서만 동작합니다. 스마트폰에서 LAN IP의 일반 HTTP 개발 주소로 플레이하는 것은 가능하지만, 그 주소에서는 PWA·오프라인 캐시를 보장하지 않습니다. 하위 경로 호스팅은 현재 기본 설정이 아닙니다. 사용하려면 Vite `base`, 매니페스트 경로, 서비스 워커 범위와 navigation fallback을 배포 경로에 맞추고 재검증하세요.

## 이야기와 챕터 확장

`src/story.js`의 데이터를 편집하면 현재 챕터의 대화·사물·수집품을 바꿀 수 있습니다. `src/life-record.js`에는 사용자가 제공한 날짜와 경력을 별도로 보존했습니다. 이 파일의 기록은 외부 검증을 뜻하지 않으며, 알 수 없는 항목은 `null`입니다.

새 사물 추가 예시:

```js
// MEMORIES에 id, 제목, 장소, 아이콘, 설명, 회상 대사를 추가
{id:'notebook',title:'낡은 공책',place:'어린 시절 집',symbol:'▤',
 text:'공책을 다시 읽어 본다.',recollection:'그때의 마음이 종이 위에 남아 있었다.'}

// 해당 스테이지 entities에 추가. art는 기존 텍스처 재사용 또는 art.js에서 제작
{id:'old-notebook',x:950,label:'공책',type:'memory',memory:'notebook',art:'pencil'}
```

NPC 추가 시 `type:'npc'`, `character`, `dialogue` 키를 지정하고 `DIALOGUES`에 대사 함수를 추가합니다. 각 대사는 `{speaker, character, text}` 형식이며, `choices:[{label,lines:[...]}]`로 분기합니다. 대화 함수가 저장 이벤트를 받으므로 완료 전후의 대사를 바꿀 수 있습니다. 모든 새 대화가 실제 기록인지 창작인지 구분해 유지하세요.

새 챕터는 다음 순서로 확장합니다.

1. 원자료를 검토하고 사용자 확인이 필요한 사건·날짜를 먼저 구분합니다. 민감한 직장 사건은 주인공의 시점으로 표현하고 실명·내부 자료를 넣지 않습니다.
2. 별도 데이터 모듈에 스테이지, NPC, 대화, 기억을 작성해 `story.js`의 등록 목록에 연결합니다. 새 장소의 `id`는 전체에서 고유해야 하며 포털의 `target`·`spawn`을 연결합니다.
3. `art.js`에서 장소 배경과 사물을 제작합니다. 기존의 `32×40`, 7프레임 캐릭터를 같은 규격의 사진 참고 스프라이트로 교체할 수도 있습니다. 프레임은 0–1 대기, 2–5 걷기, 6 점프입니다.
4. `main.js`에 해당 챕터의 시작·목표·완료 이벤트를 등록하고, HUD의 챕터 번호·제목과 chapter 1 전용 완료 흐름을 챕터 데이터에 연결합니다. 현재 `chapter:1`인 저장 정규화도 새 챕터를 인정하도록 확장합니다. 목록만 추가했다고 플레이 가능한 것으로 표시하지 않습니다.
5. 저장 구조가 달라지면 `SAVE_VERSION`을 올리고 이전 버전→새 버전 마이그레이션 함수를 추가합니다. 현재는 v1만 지원하며 더 높은 버전은 읽기 오류를 알리고 임의로 덮어쓰지 않습니다.
6. 저장 복원, 장소 왕복, 선택지, 선택 수집을 하지 않은 완료 경로, 모바일·오프라인 재실행을 검증한 뒤 `status:'playable'`로 전환합니다.

## 검사

```sh
npm test
npm run build
```

자동 브라우저 검사는 Python Playwright와 Chromium이 필요합니다. 실행 환경에 이미 설치된 도구를 사용했으며 일반 게임 실행에는 필요하지 않습니다.

```sh
python -m pip install playwright
python -m playwright install chromium
# 별도 터미널에서 npm run preview 실행
python tests/browser_check.py
```

`CHROMIUM_PATH`로 브라우저 실행 파일, `GAME_URL`로 검사할 서버 주소를 지정할 수 있습니다. 기본 주소는 `http://localhost:4173/`입니다. 검사는 실제 UI와 입력으로 전체 챕터를 진행하고 `test-results/`에 결과와 스크린샷을 남깁니다.

테스트 결과 및 사용 라이브러리 안내는 [검증 기록](VALIDATION.md)과 [외부 라이브러리](THIRD_PARTY_NOTICES.md)를 참조하세요.
