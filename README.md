# LIFE STORY
나의 인생을 담은 모바일 횡스크롤 게임

챕터 1 v1.1 — 안재원이 제공한 최신 어린 시절 기록을 반영한 **12장면 스토리 어드벤처**입니다. 기존 픽셀아트·이동·점프·멀티터치·대화·저장·오프라인 시스템을 유지합니다. **챕터 2–8은 기획 단계이며 플레이할 수 없습니다.**

## 실행과 빌드

Node.js 22.12 이상을 권장합니다.

```sh
git clone https://github.com/hayoo74-ops/life-story-game.git
cd life-story-game
npm ci
npm run dev
```

터미널에 출력되는 주소를 엽니다. 기본 개발 주소는 `http://localhost:5173`입니다. 포트가 사용 중이면 달라집니다. `index.html`을 파일로 직접 열면 모듈과 PWA가 정상 동작하지 않습니다.

```sh
npm test
npm run build
npm run preview
```

배포 결과는 `dist/`입니다. HTML5/CSS3/JavaScript, Phaser 3, Vite, Web Audio, LocalStorage, vite-plugin-pwa를 사용합니다. 외부 CDN·상업 게임 리소스·음원을 요구하지 않습니다.

## 첫 장의 이야기

| 장면 | 직접 플레이하는 내용 |
|---|---|
| 프롤로그 | 2026년 현재의 재원을 움직여 사진첩을 펼칩니다. |
| 01 학장동의 집 | 부모님과 함께 살던 집에서 가족사진을 조사합니다. |
| 02 부모님과 함께 | TV·소파·장난감 등을 살펴보고 종이가면을 착용합니다. |
| 03 액션가면 | 아버지에게 다가가 영웅 포즈와 가족이 함께 웃은 기억을 재생합니다. |
| 04 시간의 책갈피 | 특정 연도 대신 **약 1~2년 뒤**라는 상대 시간을 확인합니다. |
| 05 부서진 방문 | 어린 재원이 직접 목격한 사건을 전용 애니메이션으로 봅니다. |
| 06 달라진 가족 | 얼마 후 이혼한 사실을 확인합니다. 단일한 원인은 단정하지 않습니다. |
| 07 아버지와 단둘이 | **약 1~2년 동안**의 독립된 시기를 탐색합니다. 미확인 일상은 여백으로 둡니다. |
| 08 대연동 | 별도의 부산 남구 대연동 맵을 걸어 조부모님 댁으로 향합니다. |
| 09 공부방 | 책상·문제집과 예시 문항을 통해 엄격했던 공부 환경을 읽습니다. |
| 10 회초리의 기록 | 체벌의 경험을 왜곡·정당화하지 않고 확인한 뒤 공부 장면을 닫습니다. |
| 11 현재의 재원 | 현재의 사진첩에서 8개 기록을 순서대로 놓습니다. |
| 12 다음 이야기 | 현재의 거리를 걸어 첫 장을 마치고 준비 중인 다음 장을 확인합니다. |

학장동에서 처음부터 조부모님과 살았던 기존 시나리오는 교체했습니다. **부모님과 생활 → 함께 웃은 기억 → 약 1~2년 뒤 방문 파손 목격 → 얼마 후 이혼 → 아버지와 약 1~2년 → 대연동 조부모님 댁 → 엄격한 공부 지도** 순서를 지킵니다.

학장동의 지역 표기는 최신 사용자 기록의 ‘부산 사하구 학장동’을 따릅니다. 실제 주거지의 상세 주소·평면도는 추가하지 않습니다. 유년기 사건의 정확한 연도와 나이도 지정하지 않습니다.

## 조작과 선택 탐험

- ← → / A·D: 이동, 버튼을 누르고 있으면 계속 걷습니다.
- ↟ / Space / W: 점프. 이동 버튼과 동시에 누를 수 있습니다.
- ✦ / E: 근처 인물 대화·사물 조사·장면 이동.
- 대화창 터치 / Enter / E: 다음 기록. 선택지는 버튼을 직접 누릅니다.
- Ⅱ / ☰ / Esc: 일시정지와 메뉴. 선택지는 Tab·Enter로도 조작할 수 있습니다.

상단은 현재 장면, 하단은 다음 목표입니다. 부모님과 함께 살던 시기에는 집 오른쪽 표지판에서 골목 → 놀이터 → 문구점 → 학교 앞의 기존 맵을 선택 탐험할 수 있습니다. 이 맵들과 익명 이웃·동네 아이·문구점 주인은 **창작**이며 실제 사건이나 실존 인물로 취급하지 않습니다. 길 끝 표지판은 ✦ 버튼으로 이동합니다. 학교 앞에서는 집으로 돌아갈 수 있습니다.

공부 예시 문항은 **정답·오답·풀이 건너뛰기 모두 같은 다음 장면**으로 이어집니다. 플레이어가 일부러 틀려야 하거나 오답 때문에 체벌 애니메이션이 발생하는 구조가 아닙니다.

모든 선택 조사·기억 수집은 완료 조건이 아닙니다. 주요 사건에 딸린 기억은 진행 중 획득하며, 선택 탐험의 조각을 모두 모으지 않아도 첫 장이 끝납니다. 챕터 완료 후 사진첩에서 기록을 다시 읽고, 메뉴의 열두 장면 목록을 눌러 수집을 유지한 채 이전 장면을 재방문할 수 있습니다.

## 실제 기록과 연출 구분

대화창·회상·앨범에 출처를 표시합니다. `EVENT_RECORDS`에는 사건별 분류를, 개별 대사에는 `kind`를 저장합니다.

- **실제 기억 (`fact`)**: 사용자가 직접 제공한 사건·가족 구성·상대 시간. 직접 발언은 `우하하하! 난 액션가면!`, `액션가면은 빤쓰만 입고 있는다.` 두 문장뿐입니다.
- **연출적 재구성 (`staged`)**: 외형·가구 배치·카메라·애니메이션·효과음·현재 사진첩. 부모의 가면 장난은 화면 밖으로 처리하고 신체·속옷은 표시하지 않습니다. 방문만 파손되며 인물의 부상은 만들지 않습니다.
- **창작 (`fiction`)**: 익명 배경 NPC·선택 탐험 물건·예시 수학 문항. 가족 NPC의 일반 상호작용은 실제 발언을 흉내 낸 대사가 아니라 **‘기록 · 아버지/어머니/조부모’**로 표시한 서술입니다.

부모님 이혼의 사유·법적 절차, 방문 파손의 원인, 당시 아이의 말·행동·감정, 아버지와 단둘이 지낸 구체적 일상, 이동 이유, 체벌 횟수·욕설·상해는 추가하지 않았습니다. 체벌을 교육적으로 바람직하다고 표현하거나 모든 일상을 체벌로 과장하지 않습니다.

## 저장 v1 → v2

LocalStorage 키는 `life-story:save`, 현재 스키마는 **v2**입니다. 장면·스테이지·x 위치·진행 이벤트·조사 목록·선택·기억·퀘스트·설정을 저장합니다. 다시 시작할 때 캐릭터는 해당 위치의 바닥에 안전하게 놓습니다.

1. v1을 읽으면 원본 문자열을 `life-story:save:v1-backup`에 한 번 보관합니다.
2. 설정·플레이 시간과 이전 수집/이벤트/퀘스트 목록을 `legacyArchive`에 보존합니다.
3. 잘못된 옛 가족관계를 새 시나리오에 이어 붙이지 않도록 **새 프롤로그부터 진행**합니다. 이를 안내 메시지로 알립니다.
4. 앨범에 이전 수집 ID 목록을 따로 표시합니다. 이전 회상 문구는 실제 기록과 충돌해 재표시하지 않습니다.
5. v2의 중간 저장은 해당 장면에서 복원합니다. 컷신 도중 종료하면 잠금 화면이 아닌 사건 시작 경계로 돌아가 다시 볼 수 있습니다.

상위 버전·손상된 JSON은 임의로 덮어쓰지 않고 오류를 알립니다. 브라우저 저장이 차단돼도 게임은 실행되지만 진행 보존을 보장할 수 없다는 메시지가 나옵니다. 저장은 기기·브라우저·사이트 주소별이며 클라우드 동기화는 없습니다.

## 분량과 한계

선택 조사를 충분히 읽는 기준으로 **20–30분을 목표**로 설계했습니다. 사물 설명은 한 분기씩 약 4,100자이며 가족·익명 NPC 기록, 전용 회상, 실제 사건, 8단계 사진첩 정리가 추가됩니다. 읽기 속도 400–550자/분이라는 추정 가정과 이동·조사·선택 시간을 고려한 범위이며 **실제 사용자 읽기 시간을 측정한 결과는 아닙니다**. 주요 경로만 빠르게 넘기면 더 짧습니다. 이동 거리·반복 대사·강제 대기로 분량을 채우지 않았습니다.

- 오리지널 코드 기반 픽셀아트이며 실제 사진 기반 외형은 아직 없습니다.
- 가족 4명과 창작 배경 인물 4종을 사용하며, 시기에 따라 가족의 배치를 바꿉니다.
- 사물 데이터 28종, 기억 16종, 주요 장면 12개입니다. NPC의 여러 시기 배치는 서로 다른 실제 인물을 뜻하지 않습니다.
- 아버지 단독 동거 기간의 구체적인 일상은 추가 기록을 기다리는 여백입니다.
- 챕터 2–8은 각각 10개 항목의 설계 데이터만 있습니다. 아직 맵·플레이·엔딩을 구현하지 않았습니다.
- 모바일 뷰포트 브라우저 검증과 Galaxy S24 Ultra 실기기 검증은 구분합니다. 세부 결과는 `VALIDATION.md`를 참조하세요.

## 배포·PWA

`npm run build` 후 `dist/` 내용 전체를 **사이트 루트의 HTTPS 정적 호스팅**에 배포합니다. Cloudflare Pages·Netlify 등의 빌드 명령은 `npm run build`, 출력은 `dist`, 설치는 `npm ci`입니다. 서버 API·환경 변수는 필요 없습니다.

첫 온라인 방문 후 ‘오프라인 준비 완료’ 안내가 뜨면 브라우저 메뉴의 앱 설치·홈 화면에 추가를 사용할 수 있습니다. 리소스와 저장 데이터가 유지되면 오프라인으로 이어할 수 있습니다. 브라우저 정책·저장 공간·캐시 삭제에 따라 보존 여부는 달라집니다.

동일 Wi-Fi의 스마트폰은 개발 PC의 실제 LAN IP와 개발 포트로 접속할 수 있습니다. 일반 LAN HTTP는 플레이만 확인하고, PWA/서비스 워커는 HTTPS 또는 localhost에서 검증하세요. 이 저장소에 푸시하는 작업과 게임 호스팅 배포는 별개입니다. GitHub Pages의 `/life-story-game/` 같은 하위 경로는 Vite base와 PWA scope/fallback 설정을 별도로 맞춰야 합니다. 현재 기본 설정은 사이트 루트입니다.

## 데이터 편집과 후속 챕터

- `src/data/chapter-one.js`: 12개 장면, 실제 기록·두 대사, 사건 분류, NPC·사물·기억·맵 데이터.
- `src/data/chapter-plans.js`: 8개 챕터의 핵심·사건·장소·인물·전환점·퀘스트·선택 상호작용·감정선·분량·그래픽 설계. 게임의 여덟 장 메뉴에서도 읽을 수 있습니다.
- `src/data/chapter-list.js`: 플레이 가능/준비 중 표시.
- `src/life-record.js`: 사용자가 제공한 인생 기록. 알 수 없는 값은 `null`/빈 배열로 유지합니다.
- `src/main.js`: 진행·상호작용·앨범·UI. `src/game.js`: Phaser 이동·충돌·날씨·전용 회상.
- `src/art.js`: 배경·캐릭터·사물 생성. `src/audio.js`: 합성 사운드. `src/save.js`: 검증·마이그레이션·저장.

새 사물은 `OBJECTS`에 `lines`, `kinds`, `art`, 필요시 `memory`를 추가하고 스테이지 `entities`에서 참조합니다. 대사는 `{text,speaker,character,kind}`, 선택은 `{choiceId,choices:[{label,lines}]}`입니다. 실제 가족 대화가 없는 경우 현재의 기록 서술을 사용하세요.

아버지 단독 동거 기간은 `father-home`과 `FACTS.father`, `OBJECTS['father-record']`에 추가 사실을 연결할 수 있습니다. 새로운 사건이 확인되기 전에는 이 시기의 긍정·부정적인 생활 분위기나 대화·이동 이유를 만들어 넣지 마세요.

후속 챕터는 설계 데이터 → 실제 기록 확인 → 맵/사물/사건 제작 → 저장 스키마 및 진행 라우팅 확장 → 모바일·저장·오프라인 검증 뒤에만 playable로 바꿉니다. 현재 저장 정규화는 챕터 1 전용입니다. 단순 데이터 추가만으로 후속 챕터가 실행되는 것은 아닙니다.

## 브라우저 검사

```sh
python -m pip install playwright
python -m playwright install chromium
# 다른 터미널에서 npm run preview
python tests/browser_check.py
```

`GAME_URL`, `CHROMIUM_PATH`로 서버·브라우저를 지정할 수 있습니다. 자동 검사는 실제 UI·키보드·멀티터치를 사용해 전체 흐름을 진행하며, `test-results/`에 보고서와 스크린샷을 만듭니다. 저장 fixture를 쓰는 분기·마이그레이션 검사는 전체 플레이와 별도로 명시합니다. 일반 게임 실행에는 Python이 필요 없습니다.

외부 라이브러리 고지는 `THIRD_PARTY_NOTICES.md` 및 `public/licenses/`에 보관합니다. 최신 설계·변경 내역은 `docs/CHAPTER_1_REVISION.md`, 파일·장면·인물·수집품 전체 목록과 최종 보고는 `docs/CHAPTER_1_REPORT.md`를 참조하세요. 추가 회귀 검사는 `python tests/browser_regressions.py`로 재현할 수 있습니다.
